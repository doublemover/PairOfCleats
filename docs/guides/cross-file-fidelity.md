# Cross-file candidate fidelity

`indexing.crossFileFidelity` accepts `bounded` (default) or `comprehensive`.
It selects semantic candidate admission independently of CPU, RAM, `quality`,
worker counts and scheduler capacity. Invalid values fail config validation.
The effective analysis policy and derived signature contain the versioned choice.

Bounded mode retains the existing first-layer repository/language/novelty limits
and the propagation layer's per-chunk/global limits. Propagation uses stable
chunk identity order interleaved across files. Reordering equivalent input does
not give a different file an arbitrary earlier position in the global quota.
This is a deterministic admission policy, not a claim that every source gets an
equal number of inferred edges. Counts refer to candidates, not unique final
relationships missing from the published graph.

Comprehensive mode passes every collected supported call, call-detail and usage
candidate through both admission layers. It disables inference-lite suppression
and the parameter sample/type-candidate caps in this pass. Existing propagation
bundles, scheduler reservations and cancellation still own execution. Candidate
loops yield cooperatively every 256 visits; cancellation fails the candidate
instead of publishing a success with an unvisited tail. This mode does not make
unsupported syntax resolvable, guarantee fixed-point convergence or qualify
upstream compiler/provider coverage and downstream graph limits.

Canonical raw relations remain intact in both modes. Inference annotations live
on mutable derivatives of immutable parser facts. Native syntax call occurrences
carry exact one-based UTF-16 coordinates and typed role/resolution provenance
into `call_sites`. A malformed syntax fact fails publication rather than silently
vanishing. Legacy malformed/oversized rows retain explicit omission accounting.

The production call-site writer awaits admission into the existing row-spill
owner: at most 5,000 rows or 2 MiB of encoded row bytes per buffer, plus the
current bounded row. This charge is not a process RSS claim. The existing merge
planner opens at most 32 runs per pass and binds reusable checkpoints to input
content and comparator identity. Plain, sharded and compressed outputs consume
the sorted stream with backpressure. Failed candidate runs remain available for
retry; successful output retires them. The small in-memory `createCallSites`
helper remains for existing bounded callers.

Published `index_state.extensions.crossFileCoverage` and graph upstream metadata
retain separate first-layer and propagation counts, bounded affected chunk/file
samples, parameter sampling losses, the policy and input fingerprint. Warm cache
replay retains those observations; it does not turn budget-limited work into
complete analysis. Call-site publication has its own emitted/dropped/trimmed
receipt. Graph loading preserves the same upstream receipt across physical
formats, and risk input coverage includes it.

Architecture and impact reports expose unknown/incomplete upstream coverage.
An empty relationship result cannot establish no impact, no flow or a clean
architecture. Architecture's strict clean-verdict path remains unavailable when
coverage is unknown. Successful candidate admission and complete program analysis
are separate states; legacy generations without receipts remain unknown.

This is an unvalidated development checkpoint for #1348/#1484. Authored controls
cover both threshold layers, summary-only global exhaustion, input reordering,
strict config values, raw preservation, warm replay, canonical spill formats and
cancellation/retry. They have not run. Full semantic frontier resume, extraction
and capability sealing, resource/quota failure recovery, supported-language exact
occurrence sets, native format integration and measured memory/time remain open.
The config contract/inventory and artifact-schema reports must be regenerated by
their existing owners during the deferred validation phase.
