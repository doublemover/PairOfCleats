# Piscina fatal worker exit ownership

Date: 2026-11-05. Baseline: `3b2e659499c2d32ac10d0d605941d2464f5d29ca`, Node 26.13.0, Piscina 5.3.2. The [macOS CI run](https://github.com/doublemover/PairOfCleats/actions/runs/42028176435/job/127251005681) finished its broad lane with 1,969 passes, one failure and two established platform skips. Its only failure was `indexing/workers/worker-fatal-runtime`: the unref'ed 25-second survivor assertion fired. Windows and Ubuntu main jobs, all three native-inspection jobs, Windows native-index and authority, Rust and gate passed on that baseline. This is a JavaScript Worker shutdown defect; it is not evidence of a native access violation.

Piscina's `destroy()` waited with `events.once(worker, 'exit')`. That helper rejects when the Worker emits `error` before `exit`. Piscina's `Promise.allSettled` then finished and reset `destroying` before the original worker exited. Its later exit handler could create a replacement for the configured minimum thread count after the wrapping `IndexerThreadPool` had poisoned its generation. The wrapper retained the original Worker ownership correctly, but Piscina's new thread could survive the fixture.

The expanded real-worker regression warms the actual Piscina pool, starts fatal shutdown with a worker control, then releases a real uncaught exception or non-Error rejection. It holds only the original Worker's exit *receipt* after physical exit; all error listeners receive the actual Worker error. The test asserts that the public destroy promise stays pending until that exit receipt, original ownership stays pending, then both vendor and wrapper thread counts reach zero with ownership released. Node removes Worker listeners after its native exit dispatch, so the fixture retains and replays those original listeners exactly once. Ordinary rejection, explicit reuse, fatal poisoning, process restart and warning-mode controls remain in the same script. Before the repair, the corrected regression fails at `Piscina destroy must not settle on error before original exit` in 181 ms, with exit status 1 and successful cleanup. After the repair, both exception and rejection controls pass; their actual error types are `object` and `boolean`, and both report zero remaining threads.

`patches/piscina+5.3.2.patch` changes the TypeScript source and shipped JavaScript to await a promise resolved only by `exit`; it leaves Worker error delivery, shutdown policy, minimum-worker settings and Node/dependency pins intact. The installed package's original Git blob SHA-1s are `d727b985a81e64f6d3afea68874c308d399e5837` (source) and `9f142160c48edb65d5d0e96df5a2fe4a05365414` (runtime).
