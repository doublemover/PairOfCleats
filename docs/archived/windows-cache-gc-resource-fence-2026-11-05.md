# Repository GC respects both resource namespaces

Date: 2026-11-05. Baseline: `66176cb9a9dabe7e11b81f1a884e4974b6eb6166`. The [machine receipt](windows-cache-gc-resource-fence-2026-11-05.json) retains original failures, focused results and exact source blobs. Local `.tmp/tasks/ci-lite-1104/gc-*` and `.testLogs` paths are historical author-workspace evidence; required report contents are embedded in the receipt.

The #1574 follow-up found another production deletion bypass in `tools/index/cache-gc.js`. The collector inspected and excluded only legacy repository leases. Current storage sessions publish their durable resource leases under the launch-selected `home/state/storage-access` coordinator. GC could therefore delete an otherwise eligible generated cache while an actual modern reader still owned it. The original Windows regression removes the sentinel through an open descriptor; its lazy pathname read fails with ENOENT. An unreadable modern owner has the same defect. A resource admitted between planning and the legacy cleanup lock also loses its 124-byte generated input. The fourth original failure proves that actual file requalification had no modern exclusion barrier.

The collector now inspects both namespaces before planning. Removal uses the existing `withRepoCleanupExclusion` owner, also used by `clean-artifacts`, preserving both exclusions and the enclosing cache/repos category leases through file work and original metadata settlement. It keeps the same generated-file admission, exact identity/hash requalification, writer checks, quota semantics, saved-evidence protection and nonrecursive removal. No configuration path or caller generation label becomes deletion authority.

All four new controls pass: live resource through actual CLI/MCP and dry-run; malformed modern owner; real reader admission after planning; and actual deletion rejecting new legacy/modern readers while blocking whole-category relocation. Each retains the positive eligible deletion after confirmed release. All 25 adjacent CLI/MCP, legacy reader, saved-evidence, race and original resource/metadata settlement controls pass. All eight publication checks pass, including43/43 gate cases. Checks use Windows x64, Node26.13.0, ABI147, one job, 30-second per-case bounds, zero retries and native-status redo disabled. All four new cases are assigned to ordered ci-lite through its generated inventory; no existing lane member moved.

#1574 remains open. Its custom/external native stores still need producer/publication-backed registration and eligible category deletion/requalification; legacy and unknown stores remain protected. This repair closes a demonstrated adopted-session gap in the existing repository collector. It does not qualify optional backends, new native-store deletion, release acceptance or a complete deep suite.
