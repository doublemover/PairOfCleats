# Tantivy build settlement repair — November 4, 2026

The optional generation producer could activate a payload after a fulfilled
builder result explicitly reported outstanding native work. A rejected Promise
or later source-validation error could also release source/backend protection
without retaining the original dispatch observer. This is a P2 publication/
lifetime defect in an experimental backend, independently of package selection.

Seven new negative controls fail against the original owner: pending fulfilled
results, observer replacement, unreadable observations, revocation during real
payload inventory, original source-read failure, a fulfilled pending dispatch
and a rejected pending dispatch. Successful prefixes and original failures
remain in the [machine receipt](windows-tantivy-build-settlement-2026-11-04.json).

The producer captures at most two original observations: the immediate dispatch
and its distinct fulfilled result. It requires settlement before input/payload
validation and again before receipt activation. Failures retain those original
prerequisites inside the writer-lock scope, before either storage scope can
release. Frozen original failures, the prior receipt/payload, publication lock,
source/backend protections and bounded build slot stay owned when work remains
unknown. Ordinary Promise resolution and successful metadata writes grant no
independent native-close authority.

A settled-result positive retains successful publication and lease release. The
new build-contract identity is version 2; an otherwise valid schema-2 receipt
with the prior version 1 meaning must rebuild. Token, document and ranked-reader
semantics are unchanged. Nine new cases bring publication coverage to 21; the
existing nine reader-lifetime cases and seven source/query/cache/CLI controls remain.
All 37 native-free Tantivy cases now belong to ordered ci-lite, adding 35 previously
unlisted members. The optional real-native smoke remains separate.

No native package was installed or activated. This repair does not qualify a
compatible Tantivy binding, its native payload schema/ranking, or Windows native
rebuild/readback; #1627 remains open. The separate binding decision still needs
exact source-token/frequency/length behavior and deterministic reader/searcher/
writer disposal. Editor and physical POSIX exclusions remain unchanged. Scratch
paths in the evidence are historical author-workspace receipts.

Final formatted source passes all **37 affected cases** and all eight publication
checks, including **41 gate cases**, with zero failures, timeouts or skips.
The machine receipt retains all59 original/follow-up child files, complete
command/status/log receipts and hashes of the resulting implementation and
ordered-lane owners. No broad local suite was rerun.
