# Managed tool install allocation

The canonical declaration owner validates at most 64 exact destination records.
Each record selects one absolute root, artifact/scratch destination or managed
environment key. Required bytes must be nonnegative safe integers; optional
minimum-free and hard limits retain their existing zero/null defaults. Relative
roots, ambiguous selectors and unsafe byte values fail before writer admission.

Route projection uses that same shape normalizer. It resolves each actual root,
checks coverage for every real artifact/cache/temp destination, and compares
native root identities under the existing platform path contract. Windows case
aliases and normalized dot-path aliases identify one destination. POSIX case
spelling stays distinct. The first admitted spelling remains in diagnostics.

Equal required/minimum-free/hard budgets for that destination produce one
reservation entry, independent of object property order or omitted defaults.
Conflicting budgets fail rather than choosing one or adding speculative capacity.
Ancestor/descendant destinations are not collapsed: separate declared allocation
obligations and route coverage remain intact.

Projection is not qualification. A canonical-build-forecast remains
unqualified even if a caller adds complete/qualified booleans. The original
admission binder still refuses it, and the installer cannot acquire prerequisites
or start package writes through that forecast. Bounded archive acquisition and
matching compatible-tool reuse retain their existing owners.

The eight focused destination cases independently cover alias identity, exact
field-order equivalence, all three budget conflicts, unsafe/missing numbers,
uncovered real routes and a real managed child. The child uses two distinct
96 KiB reservations with 128 KiB hard limits, writes its known five-byte result,
then releases protection only through the original close/settlement owner.
The original projection retains three entries for the alias case and falsely
rejects a different property ordering; those original failures are preserved.
No package installation or package-build peak is inferred from this child.

The broader #1559 requirement remains: selected package/version/dependency
closure, qualified recipe-specific build allowances, all actual destinations and
real consumer/high-water qualification. Unknown npm/Go/Ruby/.NET build peaks are
not converted into arbitrary complete estimates by this repair.
