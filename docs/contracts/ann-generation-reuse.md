# Unchanged ANN generation reuse

Stage 3 snapshots the prior ready embedding state and pieces manifest before marking its new attempt pending or replacing dense-vector declarations. Reuse requires an exactly equal embedding generation and complete embedding identity. That generation already binds current source/chunk-to-ordinal mappings and every channel byte. A source edit, ordinal shift, missing channel or channel-only change conservatively rebuilds the native backends.

The selected native metadata must be checksum-authorized by the prior manifest and identify the same variant, model, dimensions, count and immutable backend generation path. Its physical `nativeBuildKey` version 1 binds normalized graph/table configuration, normalization, quantization, scale, model/dimensions, package version, Node version/ABI, architecture and platform. Unknown runtime identity or legacy metadata without this proof selects the full writer. This key records the prepared installation's logical runtime identity; it does not replace bootstrap dependency/native-byte verification.

HNSW copies its manifest-selected graph while verifying exact bytes, checksum and descriptor stability. LanceDB additionally requires a closed-writer `nativePayloadInventory` version 1 covering all regular files and directories, exact file sizes and SHA256 hashes. Inventory admission is optional, capped at 4,096 entries, 32 directory levels and 512 KiB of metadata. Added, missing, changed or unsafe entries refuse reuse. Larger datasets retain the existing full rebuild path. No hard links or mutable native handles are shared with the served generation.

Copies use bounded 64 KiB windows, explicit short-read/write progress and destination fsync, and land only inside the new attempt's private staging. Failure removes only those staged outputs and preserves prior generations. The existing backend publication owner validates each complete staged pair, stamps its new generation and publishes the manifest afterward. Reader-leased old generations remain untouched.

`annBuildWork` reports reused variants, copied bytes, invalidation reasons and child starts. Copying and verifying a dataset can cost more than rebuilding a small one. These source counters establish no latency or RSS gain. The synthetic regression covers unchanged reuse without child startup, independent copies, configuration/model-generation changes, pending-state refusal, corrupt graph bytes, changed LanceDB inventory and cancellation; it performs no native payload decoding.

HNSW copy-on-write mutation, stable chunk-label deltas, tombstone/capacity/recall thresholds, LanceDB versioned upsert/delete and reader-safe fragment maintenance remain open prototypes. Exact-oracle/native retrieval parity, old-reader/crash acceptance and measured copy-versus-rebuild costs are also unrun. No unmeasured rebuild threshold or in-place served-table mutation is introduced.
