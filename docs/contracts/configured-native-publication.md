# Configured native-store publication and cleanup

Custom SQLite and LMDB paths admit both the launch-home storage session and a store-local session before native access. The latter reuses the existing reader/exclusive protocol under the sibling .poc-native-storage/<target-sha256>/access directory. This makes the same store visible across application homes. Native files and LMDB directories never contain coordination files. All writes use ordinary current-user permissions. An existing unregistered read-only store can retain home-local admission when sibling metadata is unwritable; it remains ineligible for deletion. A registered store requires shared admission and fails before native open if it cannot acquire it.

The actual SQLite runner, LMDB builder and standalone SQLite compactor own publication. A private pre-write token binds the effective selection, launch home, canonical source generations and publication epoch. Original native work and physical close, then actual ready index-state publication, precede the bounded ready record. Full, incremental and existing zero-state SQLite return paths publish through the same owner. Nested compaction leaves its enclosing producer in charge. Existing unregistered bytes, failed/replaced attempts, shared producers, changed families and exhausted history budgets remain unqualified.

Publication metadata is internal lifecycle evidence, not a public index format or caller-provided deletion token. A configured path, marker, caller generation label, absent reader or import cannot adopt existing bytes. Records reject duplicate keys, unknown fields, malformed identities and excessive bytes/depth/tokens. Source histories are bounded and preserved when a new attempt cannot qualify. Durable home guards retain a store shared with a different application home even after that reader closes, because the other home's saved references remain unknown.

The clean-artifacts CLI and its repository-scoped MCP handler run category cleanup before canonical repository disposal. The category owner holds the existing category/repository/index exclusions, both configured coordinators and publication lock while revalidating selection, source generations, current pointers and saved/unknown evidence. Dry-run only reads; it does not open native databases or create metadata. Unknown legacy/custom stores stay protected.

Eligible apply performs bounded real native metadata operations through the original native command owner, confirms original SQLite close or LMDB physical-close callback, then rechecks publication and reference evidence before journaling deletion. It removes only the exact admitted SQLite database/sidecar family or LMDB data.mdb/lock.mdb files after BigInt identity checks. An LMDB directory is removed only when empty and still the original directory. Parent directories, registry/history metadata and unrelated members remain. A committed per-member journal permits interruption recovery without recounting missing bytes. Independent close-time retention cannot be overwritten by the cleanup journal.

Reported logicalBytesRemoved counts only files actually unlinked by the current invocation. physicalBytesReclaimed is null because filesystem allocation and sharing are unmeasured. Failure outcomes remain protected/partial and preserve original ownership observations; retries cannot declare unknown native work settled. Broad quota policy belongs to #1267. Canonical category cleanup and unadopted backends keep their existing protected boundaries.

The [Windows qualification receipt](../archived/windows-native-publication-closeout-2026-11-05.md) records original failures, focused rechecks, exact source hashes and CI membership. It does not imply whole-suite or cross-platform acceptance.
