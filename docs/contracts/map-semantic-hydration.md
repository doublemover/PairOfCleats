# Workspace semantic hydration

Canonical find, detail and trace records inherit the generation from their
projection envelope. An artifact wrapper with its own generation uses that
generation; an explicit invalid wrapper generation is rejected rather than
borrowing the envelope. Hydration admits only canonical record references and
the two-field semantic generation schema. Selected values are ordinary captured
copies, and the selected repository remains the request scope.

The request controller captures its expected generation before transport starts.
A later mutation of the caller's generation cannot authorize a sibling response.
Existing original-page and action-publication checks still guard the actual
detail button. Each inspector selection has an original private publication;
selecting a different row, reselecting the same row or dismissing the inspector
revokes its removed hydration and relationship callbacks. A mismatched response
leaves the previous evidence usable.

The actual workspace find/select/detail/operands controls use DOM emulation and
inert fetches; they are authored but unrun. Browser, serving-store and schema
integration qualification remain separate. No semantic schema or producer
meaning changes are introduced here.
