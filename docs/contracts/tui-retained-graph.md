# Native retained graph reports

The native `report.map` form uses the build recovery owner when the operator
selects an explicit `index-root`. That selector names one retained build of the
selected repository. Missing, incompatible and non-code selections fail without
falling back to a current pointer. Leaving the selector unset retains the ordinary
canonical current-index report behavior.

Preview calls `buildIndex` with recovery action `inspect`, operation `graph` and
exactly code mode. Its complete canonical plan is retained privately. The visible
review describes existing-byte validation, historical source freshness, graph
coverage limitations and preservation of the original failed build outcome.
Confirmation executes the exact retained plan once. No missing-stage resume,
source parse, embeddings or current-pointer publication is authorized.

After recovery returns a capability, the native owner invokes the exported
`withBuildGraphCapability` callback. The canonical map child receives the exact
retained root and managed `graph-capability` identifier. Its own graph reader
lease and the native outer callback remain active through the actual map read,
render and output publication. Native acceptance requires a complete successful
canonical receipt naming the exact immutable index directory and capability id.
A signal, failed child, missing identity or incomplete capture cannot become a
successful map result. The graph receipt establishes neither normal search
readiness nor success of the original failed build.

An unresolved consumer retains the original exception, observer and graph reader
recovery callback in the current native session. Status and disposal retry only
that exact callback, which must enforce the original consumer prerequisite. A
failed recovery observation is retained until it settles before another recovery
attempt. A replacement public flag, terminal job, elapsed time or new process is
not cleanup authority. Unknown cleanup with no original recovery capability
remains fenced.

The native form uses the existing typed workflow request protocol and the shared
canonical map CLI options. It adds no repository setting or caller-supplied
capability field. Browser preview remains owned by the canonical map preview
command; this adapter exports a scoped report. The authored native workflow,
real retained producer/report child, reader recovery and Rust presentation
regressions require the deferred frozen validation run. Their source is not
Windows terminal, browser or performance qualification.
