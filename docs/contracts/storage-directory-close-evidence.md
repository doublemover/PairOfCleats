# Storage directory close evidence

Status: UNVALIDATED source and authored controls, 2026-10-22.

The existing storage directory owner confirms native closure only when its
captured original `Dir.close()` fulfills with Node's standard undefined result.
False, true, zero, null, strings and objects cannot establish close evidence.
Failure preserves the exact original directory session and its independent work
prerequisites. Recovery explicitly invokes the captured original method and
receiver; a replacement method cannot authorize closure. No read or caller
operation is replayed, and confirmed close is not repeated.

Configuration preview and write admission already use this owner. An unconfirmed
close therefore cannot return an available configuration plan or treat an
inventory as ready for a new reservation. Admission retains its existing exact
coordinator until the directory and original work settle. Direct directory,
actual configuration and canonical write-admission controls exercise every
nonvoid result, exact recovery, unchanged directory contents and successful
ordinary void close. They author no child launch, physical link or user-cache
mutation.

This changes native close evidence only. Existing scope/entry bounds, directory
identity, cooperative coordination and cross-process limitations remain. No new
resource registry, deletion authority, automatic native retry or absence/PID
settlement proof is introduced. Other descriptor/atomic publication and metadata
release wrappers retain their independent work. No tests, syntax/lint/format,
bootstrap, native/platform/full-index or performance acceptance has run. No issue
completion or executable qualification is claimed.
