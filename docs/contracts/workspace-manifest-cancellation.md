# Workspace manifest cancellation

Source and authored regressions are **UNRUN** in the shared implementation wave.
No current-head runtime, supported-platform or federated-search acceptance is
claimed.

Manifest generation accepts an operation signal and stops between pointer,
mode, SQLite and member observations. Cancellation is never converted to an
ordinary missing member, even for partial read-only diagnosis. Bounded JSON
reads retain the existing descriptor borrower, check cancellation before
admitting payload bytes and resume orchestration only after confirmed closure.
Original pending observations take precedence over cancellation and preserve
their exact recovery capability.

Status, catalog and manifest commands retain signal handlers for the actual
command lifetime. JSON failure output remains one structured result; unresolved
resource settlement has its own state and never claims release. Process-local
command callers receive the original thrown observation. Read-only commands
grant no mutation authority. A failed or cancelled publishing command does not
claim no mutation merely because publication was not acknowledged.

Workspace build keeps its signal handlers through the manifest refresh after
fanout. Its receipt retains completed child observations while distinguishing a
cancelled refresh from completed publication. Refresh passes the same signal to
the existing atomic publisher and checks it before commit. Previously retained
per-mode generation roots and the canonical member identity owner are unchanged.
