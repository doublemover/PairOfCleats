# Paired finite-model interventions

The initial #1526 adapter executes isolated [finite causal models](finite-causal-models.md).
It has no source-workspace, shell, provider or trace-upload authority. The explicit
`finite-lookup-v1` adapter is selected through the offline evaluation registry;
unsupported profiles fail instead of choosing another executor.

An immutable specification binds task/split manifests, pair, question, world,
task/branch/assumption revision, one original exogenous support assignment,
assigned mechanism replacements, output definitions, held-fixed conditions and
a declared negative-control relation. The only estimand is the same-unit contrast
inside that supplied model. Planning validates the original model and admitted
typed values without evaluating it. Aggregate equation work must fit the declared
bound before either pass starts.

Replay actually evaluates baseline and treatment on the same original assignment.
All nonintervened descendants recompute. Before publishing, the owner verifies
every replaced/unreplaced trace step and derives realized replacements from those
steps. Assigned and realized identities remain separate. The receipt retains
original/constant mechanism hashes and factual/realized values. Replacing a
mechanism by its current value can be realized successfully with equal outputs;
output stability is not failure of realization or evidence of source irrelevance.

Held-fixed values must hold in both actual passes. Violations make the pair
inadmissible and the negative control unevaluable, rather than blaming a model.
Declared contradicted assumptions retain an assumption-dependent status. Passing
finite controls can qualify the declared model contrast; source support, origin
independence, model reliance, executed task outcome and program causal effect stay
separate unmeasured axes.

Each actual execution has a unique run/role identity, including repeated runs of
identical inputs. Deterministic comparison identities identify equal semantics
without deduplicating actual cost. Both passes, model preparation, planning,
serialization and aggregate equation work are reported. There is no warm-baseline
cache or free shared execution claimed. Output is bounded by the declared
128 KiB maximum; failed projection/cancellation publishes no owned receipt.

`comparePairedFiniteHypotheses` accepts original plan/pair/prediction receipts.
The realized intervention, full output definitions, factual conditioning, planned
held-fixed requirements, world and revisions must match. Missing predictions or
failed admissibility do not eliminate a model. Complete model exclusions remain
qualified to the authored finite system. `compareInvestigationFiniteModelPair`
also checks the current investigation projection, without adding an observe or
admit-support event. A hypothetical/model replay is not an observed program run.

Five unexecuted cases cover actual descendant replay, identical/no-change
controls, realized-versus-assigned identity, distinct execution cost, failed held-
fixed conditions, contradicted assumptions, direct/common-cause discrimination,
late revision rejection, unavailable factual premises, strict adapter selection,
bounded output/work, private receipts and cancellation.

This profile supplies the deterministic finite-system/revision seam. The
[origin/trace baseline](origin-observation-evaluation.md) separately evaluates
lineage and reported transfers. Independent source-support attacks, task executor,
clustered paired reporting and optional provider qualification remain #1526 work;
this adapter does not establish those qualifications.
