# SQLite original-resource admission

The existing SQLite operation owns its admitted repository, temporary,
configured and exact resource leases through accepted work and finalization.
Before admitting another target or accepted child, it requires every retained
original resource observation to be settled. Accepted work checks again at
dispatch, closing the interval between promise admission and actual execution.
Unknown observation overflow refuses further dispatch. Ordinary diagnostics
whose original resources have settled retain their existing fallback behavior.

A failed admission remains blocked for the operation. Later original physical
settlement can permit explicit metadata recovery; it cannot reopen that failed
operation for another native route. Already started work and original native
finalizers keep their existing drain and close owners.

Successful operation and child results also cross the original observation
boundary. A returned object is not evidence that independently pending work has
settled. Its original observer and independently thrown inspection causes remain
required until confirmed; copied properties cannot substitute for those owners.

This introduces no registration, publication/deletion authority, new retry,
configuration knob or native-close replay. Custom/external producer registration,
eligible category deletion and broader adapter/native qualification remain
separate scope. The new actual-file/native controls are authored and unexecuted.
