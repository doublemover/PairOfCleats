# TypeScript compiler selection

The programmatic compiler bridge follows its explicit resolve order for genuine
package absence. Untrusted repository packages remain unexecuted. Once an entry
is selected, module evaluation, byte capture and compatibility failures are
terminal for that invocation; another installed compiler cannot replace that
failed owner. A present package with a missing legacy compiler entry is an
incompatible/damaged selection, including native TypeScript API packages whose
distinct adapter is required.

Resolution and filesystem error fields are read through the original resource
observation owner. Module-evaluation failures need no absence classification;
frozen, pending and falsy original throws remain retained without inspecting an
arbitrary diagnostic accessor. A module's missing transitive dependency is a
selected-module failure, rather than proof that the compiler itself is absent.

The semantic compiler-bindings producer is version31 and the TypeScript provider
is3.0.2. Existing syntax/LSP producers keep their own versions. Derived replay
cannot reuse the prior silent-fallback meaning. This repair does not qualify or
complete the distinct TypeScript7.1 API adapter.

Seven authored, locally unrun controls execute actual Node module selection and
controlled original failures. They cover async/sync loaders, pending observations
with mutating diagnostic accessors, native-package layout refusal, falsy throws,
genuine absence, trust refusal and the original complete compiler positive.
Vendor API, native lifetime and source-consumer qualification remain separate.
