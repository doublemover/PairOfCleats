# Managed verification observations

The original managed verifier captures its result or thrown value before reading
settlement. The existing storage-observation ledger retains that first observer,
the original nested receipt, field inspections and callback failures. Every
settlement/capability field checks all retained prerequisites before and after
access. A later field cannot erase an unconfirmed interval in an enclosing owner.

Receipt shape remains exact: `resourceId`, `settled:true`, `pending:false`, with
the actual invocation identity and no unknown enumerable fields. A positive
verification remains an object. Successful capture and arbitrary copied receipt
fields do not provide independent native-close proof. The existing install/reuse
owners retain their resource phase until actual original work and exact recovery
requirements are satisfied.

The selected-generation consumer reads the same private result observation,
including nested receipt prerequisites. Diagnostic aggregation uses an own data
message; it does not invoke a pending original message accessor. Frozen and
function-valued failures retain their original cause/receiver. Ordinary receipt
getter failures retain their existing explicit recovery path.

Nine authored, locally unrun controls exercise the actual verifier with finite
result/receipt/inspection models: early result/failure observations, nested and
enclosing guards, capability revocation, independent inspection/callback errors,
function failures, exact refusal and the original closed positive. These models
do not qualify vendor packages, native handles or real child retirement.

The installer carries those original observations through post-verification
directory/file inventory, generation promotion, immutable receipt and selector
publication, and each cleanup phase. Atomic publication checks the original
prerequisites again at commit. Unknown work retains staging and the previous
selector; it cannot become a following acquisition or successful publication.

Pending failure journals use inert owner diagnostics and do not reenter the
progress callback. Once diagnostic reads are admitted, each field rechecks the
original ledger. Independent inspection failures join that ledger before error
composition, so a later message getter cannot erase their interval. Owner-created
error compositions retain their original causes and context without recursively
adopting their own aggregate observer.

Six further authored, locally unrun cases exercise actual managed publication,
reservations, staging and original recovery with explicitly inert archive/verifier
callbacks. They retain unread pending diagnostics, independent inspection work,
function-valued originals, progress admission and nested receipt observations
revoked during the original post-verification directory open. The preceding
selected generation remains unchanged, and recovery does not repeat acquisition.
The download control uses the real response-session owner with a deliberately
blocked response cancel and a failed transaction-journal rename. Recovery retains
the original session across error composition and awaits its actual closure.
The transport's `downloadCleanupError` field retains the exact cancellation
failure. The outer install boundary also exposes that error through the generic
graph, alongside the original download and journal errors. Checks retain both
the exact producer-owned field and the promised generic graph edge.
Actual vendor packages and native lifetime qualification remain separate.

Recovery receipt validation uses the same field-by-field observation owner,
separate from the outstanding work it may explicitly reconcile. Original receipt
and inspection prerequisites are retained across recovery attempts. A later
literal cannot replace them, and no resource lease releases until they settle.
Five authored, locally unrun finite controls exercise the actual retained
verification owner, including early and mid-field pending observations, field
and shape inspection work, invalid identities and the original closed positive.
Install, descriptor-close reconciliation and removal reuse this receipt guard.

The Go SDK version probe uses the same ledger before projecting status, signal,
capture limits or output. Nested field results join the ledger before another
read. Failure termination diagnostics are admitted only after retained original
observations settle. The ledger exposes the first privately captured original
observation without rereading a replaceable callback property; that observation
grants no independent child-close or metadata-release authority.
Actual close/tree requirements remain distinct from independent resource guards,
and the projected report retains the original guards for its consumer. Seven
authored, locally unrun finite controls cover early/nested/mid-field refusal,
original failure/inspection/function values, the closed positive, truncation,
nonzero status and late guard revocation. Existing real SDK/native qualification
remains separate from these injected spawn results.

The SDK transaction keeps the original verifier/receipt observations through
capability projection, binary hashing, generation promotion, pointer activation
and each cleanup mutation. Receipt writes use the existing atomic-file owner
with a commit prerequisite. Download reconciliation retains the original branded
response session, and archive recovery uses exact guarded receipts. Four further
authored, locally unrun integration controls use the real transaction/storage
owners with inert archives/probes: root/nested capability revocation, an original
post-verification file open and function-valued failure retirement. The selected
old SDK remains usable and recovery does not repeat either download.

HTTP download classification now uses the canonical bounded storage ledger.
Its sole local callback-aggregation loop is retired; body/iterator cancellation,
original stream draining and branded download-session authority stay with the
transport owner. Classification follows original body teardown, checks retained
prerequisites around each field and stops after independent inspection work.
Function-valued failures retain their identity without string coercion.
The common error composer accepts an internal literal `ownerMessage` so an
immutable pending failure can retain its descriptors/causes without evaluating
its message getter. This changes no public command or response schema.
Five authored, locally unrun controls cover early/function/inspection refusal,
actual original recovery, bounded response success and an ordinary HTTP rejection.
The callback control retains a second pending inspection after the first original
changes from false to throwing to true; neither callback replacement nor later
settlement drops that independent obligation.
