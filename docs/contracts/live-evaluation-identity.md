# Live evaluation identity and observed execution

Live judged reports version 2 retain the actual matching mode and a selected-input
identity. Ordered queries, selected cohorts, captured silver/gold judgments,
limit and metric/depth policy own that identity; the dataset pathname remains
human provenance. Each occurrence has its own case ID. Historical vector/fusion/
task replay sections retain their separate evidence scope.

Retrieval output now carries the existing effective query-policy hash through
the rendering boundary. It exposes a hash rather than raw configuration or
credentials. Per-case evaluation receipts capture selected modes, requested and
observed backend, selection reason, fallback/fidelity, generation/surface/profile/
signature identity, actual per-mode sparse/ANN/reranker outcomes and cache facts.
Requested ANN or backend flags do not certify execution. Missing evidence is
explicitly unqualified; already admitted numerical observations remain useful.

Repeated receipts are interned with case references. Retention is bounded to
256 receipts, 8 KiB per receipt and 512 KiB of retained receipt bytes. Source signatures are hashed
under the same 8 KiB input admission. Live case identity admission allows 128 KiB
per captured query/judgment frame. Accessors/inherited fields cannot supply
passive evidence. Unknown or over-budget receipt retention cannot become a
qualified experiment. Cache facts remain per case and do not invent system
configuration changes.

The run compares generation identity across selected modes and effective system
identity within each declared cohort-selection context. A changed generation,
backend or effective policy is explicitly mixed. Different planned selection
contexts retain their own mapping. This observes consistency across independently
pinned requests; it does not claim a new run-wide native generation lease.

Strict model-bakeoff comparison requires intact matching input/metric policies
and a complete stable execution registry. Missing, fallback-derived, partial,
mixed or truncated execution evidence cannot authorize its quality recommendation.
Receipt and registry hashes detect inconsistent handoffs, not independent proof
that an untrusted producer actually performed work. Resume source identity
includes the new observation owner. Descriptive live reports can retain unknown
provenance without passing the strict comparison gate.

The actual-runner fixture uses inert search/filesystem/display seams and the real
retrieval metadata producer. It covers equal scores from different backends,
stable and changing generations/policies, fallback, missing metadata, actual
versus requested ANN, cache interning, changed queries/judgments/matching mode,
passive admission and registry integrity. This contract coverage does not qualify
a native model/backend or a physical performance experiment.
