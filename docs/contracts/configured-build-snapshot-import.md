# Configured build snapshot import

Implementation status: UNVALIDATED. Source-only CMake/Make fixtures are authored and unrun; no configure/build/dry-run/query process has been invoked.

The read-only importer accepts explicitly supplied CMake File API v1 reply bundles with codemodel-v2 or versioned Make target/prerequisite/output receipts. Independently retained producing receipts bind reply bytes, observed producer profile hash, source closure, generation and selected configuration/variant. Unknown/incomplete/stale/conflicting receipts fail. CMake roots are explicitly remapped, outside-root paths fail, configuration selection must be unique, and raw backtrace evidence remains attached. CMake `dependencies` are labeled build-order relationships rather than silently becoming direct link dependencies. Make variable/pattern prerequisites remain unresolved and no Make expansion is attempted.

The admitted snapshot object is branded by the importer. The existing import build-context owner accepts that object, adds its identity to the cache fingerprint and exposes `configuredDependenciesFor` source/target witnesses separately from textual import classification. The engine forwards an explicitly supplied snapshot; it does not discover files or launch a build. New public configuration knobs are not introduced.

The authored `tooling/providers/configured-build-snapshot-context` fixture compares differing configured dependencies, provenance/fingerprints, source receipts and outside-root refusal. CMake cache/toolchain/full input closure interpretation, Bazel cquery/aquery/repository mappings, Docker stage/resolved-image tiers, compiler-context binding, canonical persistence and context/impact consumer integration remain pending. Primary bases: [CMake File API](https://cmake.org/cmake/help/latest/manual/cmake-file-api.7.html), [Bazel cquery](https://bazel.build/query/cquery). This partial source increment does not close #1194 or qualify a tool release.
