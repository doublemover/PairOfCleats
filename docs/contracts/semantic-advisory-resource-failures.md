# Semantic advisory resource failures

Status: UNVALIDATED source and authored controls, 2026-10-22.

Provider evidence detail, literal-source fingerprints and optional source
references check the existing original resource observation before classifying
an exception as budget-limited, missing or timed out. A failed original close
shaped like `ERR_FILE_TOO_LARGE`, `ENOENT`, an output limit or `AbortError` cannot
become a successful partial page, incomplete hash or optional-navigation warning.
Pending ownership is checked before caller-abort projection as well.

Each classifier captures the original observation before reading diagnostic
code/name fields, rechecks it afterward and retains it with an independent
inspection exception. Missing provider evidence remapping preserves its captured
original cause/observation. Replacing an error's callback during inspection
cannot authorize advisory output. Ordinary settled budget/missing/timeout
behavior and existing response/cursor limits remain unchanged.

These consumers add no native owner, retry, registry or release capability.
Actual failed descriptor recovery remains with the privately authenticated
contained-file session on the original error. It never replays evidence/source
reads or publishes an advisory result after close-only recovery.

The authored fixture uses actual source-linked writer/store detail and original
sidecar/source FileHandle close faults, including concurrent caller cancellation,
diagnostic getter mutation/falsey/pending inspection errors, literal fingerprint
budget lookalikes, and a real optional source-reference deadline. Settled budget
and successful literal controls remain. It has not run. Outer transports and
generation/lease retention, arbitrary abandoned callbacks, native/platform/full
build and performance qualification remain separate. No producer/schema/format
meaning changes.
