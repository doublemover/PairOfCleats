# Source-linked report bounds

All eight current source-linked adapters finalize the complete canonical report through the same pure byte-admission helper. The existing producer allowance includes the final 64-digit content identity, UTF-8 encoding, original wire artifact where present, repeated target witnesses and expanded declaration metadata. Input size and record counts do not stand in for serialized output size.

GraphQL and explicit template registry reports retain their declared 500 KiB output bound. Proto, SemanticDB, ShellCheck, SQL, Astro mapping and JSON-reference reports use the existing 1 MiB report/writer ceiling. The helper reserves the final identity entry and uses [bounded canonical encoding](semantic-json-byte-admission.md) for the remaining report allowance. It charges keys, values and JSON escaping before encoded expansion, rejects unsupported JSON/getters before spreading it, and returns a canonical owned copy. Existing provider error codes and cancellation/time checks propagate; an oversized report throws instead of returning a truncated report or advertising a complete prefix.

Each affected adapter/report identity advances from `1` to `2`. The report schema, canonical hash domain and common durable writer remain unchanged. This does not qualify application module closure, compiler/runtime behavior, native tools, ordinary source discovery or all report-to-detail paths. The writer still independently admits the complete immutable sidecar and storage operation under its own allowance; producer admission does not promise publication success.

The supplied Proto, SemanticDB and ShellCheck report routes advance their local adapter/report identities to `3` and capture producing receipts and generation under their existing 1 MiB producer byte allowance. This records the stronger input-admission and context-ownership rule. The bounded canonical encoder admits JSON escaping, keys and arrays before cloning. It hashes the admitted encoding with the existing receipt domain, preserving the receipt content identity without a recursive second walk. Each route copies artifact bytes and captures receipt/context before consulting an external cancellation hook; its independent time-only check still bounds capture work. Unknown receipt fields remain part of the exact hash and cannot escape byte admission. Missing receipts still return non-authoritative evidence after cancellation checking. Astro, SCIP and other producer-input routes have separate admission owners and no additional input-bound claim here.

Complete report finalization likewise hashes its already admitted canonical encoding, so deeply nested admitted data no longer adds a second recursive identity walk. These changes do not alter valid canonical hashes or raise report/source/artifact/fact limits. Receipt and generation allowances bound those individual owned copies; their sum, caller-owned source inventories, engine enumeration, source joins and other downstream owners retain separate limits.

Authored regressions check the exact UTF-8 boundary including identity bytes, escaped control-character expansion, metadata keys, undersized identity allowance, canonical ownership, getter rejection and interruption, plus actual Proto descriptor and GraphQL producer paths whose bounded inputs expand beyond their advertised output allowances. Additional input controls cover large sparse arrays before enumeration, nested input/report hashes and all three receipt routes rejecting oversized input before wire/library decoding. Actual Proto, SemanticDB and ShellCheck fixtures mutate caller artifact/receipt/generation during cancellation inspection and require the original captured evidence. Parser inventories and producing receipts are synthetic. All remain **UNVALIDATED**: no fixtures, library/compiler/native/server execution, syntax, format, bootstrap, source execution or performance acceptance was run. Bounded streaming/resume of a report rejected at these current fixed output limits remains future work.
