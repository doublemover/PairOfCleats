# Source-linked report bounds

All eight current source-linked adapters finalize the complete canonical report through the same pure byte-admission helper. The existing producer allowance includes the final 64-digit content identity, UTF-8 encoding, original wire artifact where present, repeated target witnesses and expanded declaration metadata. Input size and record counts do not stand in for serialized output size.

GraphQL and explicit template registry reports retain their declared 500 KiB output bound. Proto, SemanticDB, ShellCheck, SQL, Astro mapping and JSON-reference reports use the existing 1 MiB report/writer ceiling. The helper checks encoded nested objects and the final identity-bearing envelope, rejects unsupported JSON/getters before spreading it, and returns a canonical owned copy. Existing provider error codes and cancellation/time checks propagate; an oversized report throws instead of returning a truncated report or advertising a complete prefix.

Each affected adapter/report identity advances from `1` to `2`. The report schema, canonical hash domain and common durable writer remain unchanged. This does not qualify application module closure, compiler/runtime behavior, native tools, ordinary source discovery or all report-to-detail paths. The writer still independently admits the complete immutable sidecar and storage operation under its own allowance; producer admission does not promise publication success.

Authored regressions check the exact UTF-8 boundary including identity bytes, canonical ownership, getter rejection and interruption, plus actual Proto descriptor and GraphQL producer paths whose bounded inputs expand beyond their advertised output allowances. The Proto receipt/parser inventory is synthetic. All remain **UNVALIDATED**: no fixtures, library/compiler/native/server execution, syntax, format, bootstrap, source execution or performance acceptance was run. Bounded streaming/resume of a report rejected at these current fixed output limits remains future work.
