# Finite view composition

The closed `finite-adjacency-composition-v1` offline profile composes the existing
select/project, inner/anti-join and grouped adjacency maintainers. Its definition
declares at most16 original inputs,16 topologically ordered stages and16 named
outputs. Each edge must match the original declared domain. Copied handles,
unknown operators, callbacks, cycles and undeclared outputs are rejected.

Stages retain exact natural-number multiplicities, immutable support identities,
input roots and captured-domain completeness. Select and join supports remain
compressed coefficients. Complete grouped rows have coefficient one; only those
bounded rows are projected through the existing occurrence cursor. An incomplete
group exposes no exact aggregate rows. Incomplete anti-join inputs retain the
existing unknown/withheld behavior instead of proving absence.

## One source advance and atomic stages

The adjacency owner privately seals each successful original transition with its
exact base, captured batch, signed support changes and destination handle.
Prepared unary/join entry points verify that receipt through the same owner.
Editing or copying a public result cannot replace its privately captured state.
Several stages and both roles of a self-join therefore consume one original
source advance. Existing standalone operator entry points retain their original
transition path through the same implementation.

An unchanged join role uses an original identity observation. It neither advances
that input's replay ledger nor creates a different private input root. This keeps
later updates aligned with the actual shared source. Derived output transitions
also retain the original adjacency support-history owner. Group projections use
the exact original group identities, including retained alternatives.

All source transitions, affected stages and derived outputs finish before a new
cohort is returned. A downstream allowance, cancellation or contract failure
leaves the original reader cohort intact. Identical outer replay is a no-op;
changed replay, stale bases and inner replay under a new outer ID are refused.
Unchanged branches keep their original stage/output handles.

## Bounds and checkpoints

Default bounds are8MiB of logical retained serialized state,262,144 admitted work
units and128 revision/invalidation records; callers may only tighten them.
Original source/support-history bytes are measured by the adjacency owner and
charged once for shared handles. Stage reports, derived traces and the cohort
receipt are included. Source admission, actual operator row visits and projection/
delta work are counted separately from encoded-byte limits. These are logical
resource bounds, not measurements or hard limits on V8 heap, RSS or total CPU.

Existing maintainers select their sparse, affected-group or role-ordered paths
and dense fallback. The composition receipt reports each selected strategy and
work counters. No calibrated latency or production speedup is claimed.

At the revision bound, an explicit checkpoint rebuilds stage arrangements under
the same current original inputs. Source support histories remain retained.
Logical output relation roots must equal a clean rebuild. A checkpoint cannot
clear a pending observation invalidation. Spill, durable shared manifests,
crash-restart publication and measured elastic cost history remain separate work.

## Invalidation and independent components

An exact, replay-bound invalidation targets declared source/stage identities and
withholds only their downstream outputs. Original historical readers keep their
old cohort. Independent outputs remain readable and can accept unrelated source
updates. Updating an invalidated component requires a new bootstrap; an unchanged
batch or caller freshness boolean cannot clear the invalidation.

This is a supplied finite-model boundary. It does not confirm a live compiler,
solver or provider observation, publish a semantic generation or establish source
freshness. Those production owners must supply their own complete input and
observation evidence before adopting the cohort.

Twelve authored, locally unrun controls cover closed DAGs, chained operators,
shared-source self joins, unchanged-role followups, passive/replay admission,
atomic refusal, incomplete negative domains, independent invalidation, original
prepared receipts, independent expanded-bag and clean-root parity, very large
coefficients without expansion, and checkpoint/source-history parity.
