# Native owned-service controls

The workflow service picker lists API, MCP and indexer instances already admitted
by this supervisor session. Its serviceId binds the exact private job object and
scope. A status PID, discovered endpoint, reused job ID or other session cannot
acquire a stop capability. Native review requires the exact selected service and
explicit confirmation before cancellation reaches the existing job owner.

The existing job settlement and protocol resource maps remain separate witnesses.
Stop requests await execution and inspect exact resource removal before claiming
closure. Terminal/replaced jobs with unknown resource closure retain their bounded
slots and diagnostics; they cannot accidentally cancel replacement jobs. Failed
observation remains unconfirmed. Health and published-index readiness are never
inferred from service ownership or child exit.

The same six-slot owner reserves capacity before supervisor job admission. Pending
launches count against that limit across asynchronous admission. Binding transfers
one exact scope/kind reservation to its admitted job; rejected admission returns
only its unbound reservation. Capacity exhaustion cannot first launch a service
and then fail while registering its control.

API and framed-protocol owners retain the original pending subprocess error.
Promise rejection is never converted to resource-map removal or a closed result.
API disposal can reconcile the original exact-handle delayed-close observer;
failed tree cleanup remains protected. Framed disposal returns closed:true and
pending:false only after its canonical child owner confirms settlement. MCP and
semantic continuations require both fields before erasing their resource entries.
Combined operational/cleanup failures preserve the pending marker and exact
reconciliation predicates. These are direct-child guarantees, not a descendant
census; actual Windows containment still requires separate qualification.

The native workflow exposes the picker with `v` from commands/results, refreshes
with `t`, and preserves opaque service selection through observations. The
supervisor's typed services/stop-service requests retain strict scope and
confirmation schemas. Shutdown/reset uses existing attempt-all closure owners.
Graph-evidence and machine-local storage-policy commands have explicit unsupported
native dispositions until their exact build/policy review forms exist; their
canonical CLI remains available.

Source and injected-owner/native-state regression assertions are UNVALIDATED.
Actual Rust build, protocol execution, ConPTY/service startup/shutdown, descendant
and terminal lifetime acceptance remain in the deferred Windows batch.
