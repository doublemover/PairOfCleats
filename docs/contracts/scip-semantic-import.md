# SCIP semantic import and LSIF compatibility

Implementation status: UNVALIDATED. Deterministic source-only fixtures are authored and unrun. No scip-clang or rust-analyzer artifact is newly qualified.

The existing SCIP CLI flat projection now reuses extracted format helpers with its compatibility shape preserved. The richer importer accepts one bounded complete UTF-8 JSON Index using camelCase or protobuf snake_case field spellings; conflicting spellings fail. Binary protobuf and JSONL rich framing require an admitted pinned decoder/converter and currently fail explicitly. [Official SCIP protocol](https://github.com/scip-code/scip/blob/main/scip.proto) is the format basis; the decoder does not execute a converter.

`loadScipSemanticSources` constructs source/target inventory from immutable parser partitions and retained original bytes. `prepareScipSemanticImport` requires an independently retained producing receipt binding exact artifact hash, profile hash, producing root, generation, project variant, source bytes, syntax partition and generated mapping. Unknown receipts produce non-authoritative output; they cannot enter the writer. Root mappings are explicit, paths cannot escape or conflict, encodings must be declared and exact UTF-8/16/32 mapping must succeed. A current working-tree hash alone never establishes an old index's freshness.

The source loader uses one bounded retained snapshot capture to reconstruct the complete canonical manifest and joins its source/hash identity back to the parser inventory. The shared exact-coordinate owner rejects UTF-16 surrogate splits as well as clamped ranges. Internal semantic adapter version 3 includes the shared LSP coordinate version in prepared input, context and producer identity; old coordinate or receipt-ownership meanings cannot reuse an immutable derived partition. The SCIP JSON format and original producing-receipt schema remain version 1. This is an internal semantic migration, not new producer execution authority.

Before consulting an external cancellation hook, the importer copies artifact bytes and captures the producing receipt, generation and project variant through bounded canonical JSON. Receipt/context capture uses the existing `maxBytes` allowance (1 MiB by default, with the existing maximum of 16 MiB) for each individual owned input. The existing receipt hash domain hashes that admitted encoding, so valid receipt hashes remain identical without a recursive second receipt walk. Prepared generation/variant no longer alias the caller's nested objects. Oversized escaped metadata and unsupported getters fail before receipt authority can be accepted. The common input helper accommodates SCIP's existing maximum; Proto, SemanticDB and ShellCheck still pass their unchanged 1 MiB declaration ceilings.

Authored controls mutate caller artifact, producing receipt, generation and nested project variant during cancellation inspection and after preparation, then follow the captured result through the canonical writer/sink/detail path. Other controls retain unknown receipt behavior, old adapter rejection, exact UTF-8/16/32 mapping, byte admission, getter rejection, configured larger allowance and abort. These remain unrun. Bounds cover those individual captures, not their sum or caller-owned parser inventory, downstream context hashing, complete importer memory, time, converter execution or real producer qualification.

Local symbol identity includes its document source identity. Global symbols remain scoped to artifact, generation and project variant. Existing admitted definitions/references are joined conservatively; unsupported relationships remain counted and retained in evidence. External definitions stay heuristic without matching admitted definitions. Occurrence roles do not invent calls, CFG, macro internals or exact type trees. The writer emits existing evidence/binding/reference records through the common immutable sink and preserves raw metadata, document and external-symbol evidence. Query acceptance is exercised only by the authored `indexing/semantic/scip-source-pinned-import` fixture, which has not run.

The existing LSIF CLI remains a flat compatibility importer with its current item-direction/URI controls. It is not a rich semantic publisher. Result-set/next/moniker/package linkage and source-context validation must be implemented through the same bridge before rich LSIF publication is supported. No alternate occurrence store is added.

Remaining issue #1196 obligations include a version-pinned official binary decoder/converter, CLI/import scheduling integration, duplicate/local/external/variant/generated fault matrices, cancelled converter handling, real scip-clang and rust-analyzer producing receipts, and published navigation/detail proof. This source increment does not close the issue.
