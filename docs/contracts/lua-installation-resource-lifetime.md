# Lua installation resource lifetime

Status: **UNVALIDATED implementation and authored source regressions**. No install, bootstrap, tests, syntax check, formatting, native execution or filesystem acceptance was run.

The existing Lua cache installer uses the shared bounded Zip/Tar.gz extractor, replacing its separate AdmZip `extractAllTo` and `tar.x` paths. Its limits are private recipe constants: 128 MiB compressed input, 256 MiB expanded total, 128 MiB per entry and 50,000 entries. Release metadata uses the existing owned download body with a 2 MiB bound. Local selected archives are read through their original FileHandle in bounded chunks with before/after extent/timestamp checks and exact close ownership. The local source is never a deletion target. Pending source ownership stops automatic retry even if an HTTP/error classification says retryable.

Extraction writes inert regular files. Before staging, POSIX Lua explicitly applies executable mode to the selected command. Staging and selection publication recheck the runtime files and executable permission; the existing managed resolver also refuses a POSIX selection whose command lacks executable permission. These are layout/mode checks, not executable or protocol qualification. Windows layout remains a nonempty regular executable file plus `bin/main.lua`.

Original staging and temporary-directory identities remain with the shared archive resource owner until copy hooks, extraction, cleanup and their independent original observers settle. A pending copy or stage cleanup keeps the actual publication lock and temporary/staging bytes. Recovery uses the non-enumerable actual `archiveExtractionSession`, then removes only exact owned directories and releases the captured lock. Failed lock publication is adopted only through the existing private FileLockPublicationSession producer identity; a copied property, PID or cause is insufficient. Recovery never replays copy, extraction, download, a hook or selection publication.

Frozen and falsey failures remain exact causes instead of receiving direct `recovery`/`cleanupErrors` mutation. After generation promotion, failure includes a read-only diagnostic recovery context identifying the retained replacement and existing pointer, with `priorGenerationRetained:true` and `deletionAuthority:false`. Earlier recovery/cleanup fields survive on the exact original cause. The retained promoted generation is never removed by staging or temporary cleanup. Current-selection bytes are rechecked by the existing publication owner, including after the before-selection hook.

The installer still implements structural package installation and its existing selected-generation metadata. This batch does not invent native/protocol verification, durable category admission, a new storage namespace, archive authenticity beyond the existing source/digest contract, or cross-process recovery of in-memory capabilities. Unknown original native observers remain protected. Portable pathname comparison/removal is not atomic against hostile concurrent replacement, and high-level copy API/platform acceptance remains deferred.

Only the obsolete Lua-local archive import/implementation was removed. `adm-zip` remains required by `tools/tooling/vsix-container.js`, `tools/tooling/archive-determinism.js`, `tools/release/verify-surface.js` and actual archive/VSIX/release fixtures. `tar` remains in the lockfile as a transitive native-build dependency. No package, lockfile, patch, native-build or permission policy entry was removed or loosened. This archive work does not claim completion of the separate tree-sitter-lua consumer/dependency issue.

`lua-resource-recovery.test.js` authors actual local Zip/Tar.gz installation, frozen primary plus independently pending cleanup, falsey copy failures, frozen post-promotion recovery, source close/no-retry/no-deletion, real generic lock publication recovery and POSIX mode controls. Existing `lua-language-server-install.test.js` retains its actual CLI smoke, replacement/unknown-selection controls and package layout checks. All remain unexecuted for this batch.
