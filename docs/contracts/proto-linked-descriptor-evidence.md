# Linked Proto descriptor evidence

Implementation status: UNVALIDATED. Source and a wire-format fixture are authored; no library invocation, protoc/Buf process, test, formatter, gate or published-consumer qualification was run. Issue #1191 remains partial.

`prepareProtoDescriptorEvidence` accepts a complete binary `FileDescriptorSet`, capped at 256 KiB, decoded through the existing application protobufjs **8.8.0** descriptor schema. It requires an independently pinned producing receipt: artifact hash, actual producer family/version/profile hash, config/dependency/lock/custom-option identity, include roots, generation, descriptor-to-original-source mapping, source hashes and immutable parser hashes. Missing producing authority returns an explicit non-authoritative result with no report. Rehashing a current working tree cannot supply authority for an older descriptor artifact. No compiler, include loader, package resolver, hook or network is invoked.

The adapter retains fully qualified messages, fields, enums, services and methods; field numbers/labels, scalar type codes, streaming flags and known descriptor options stay evidence metadata. Exact descriptor paths select `SourceCodeInfo` name/type/import ranges. [Protoc defines source columns as byte counts with tab stops of eight](https://github.com/protocolbuffers/protobuf/blob/main/src/google/protobuf/io/tokenizer.h), so mapping walks original UTF-8 code points and rejects positions inside a character or tab expansion. The adapter does not treat those columns as LSP UTF-16 offsets. Preambles and CR/LF bytes remain part of the original source identity.

Only proto2/proto3 source-linked features are admitted by this adapter profile. Editions remain explicit unsupported metadata with no derived reference targets. Duplicate fully qualified names, conflicting locations, stale sources, wrong generations and escaping descriptor/import names reject admission. Missing imports, unavailable source information, non-absolute type names and external descriptor sources remain unresolved. Type/method source witnesses require the producing descriptor's fully qualified target and its direct/public-import visibility closure. Cycles are bounded diagnostics. The compiler-generated runtime's dispatch and call flow are outside this evidence.

Original descriptor wire bytes are retained exactly in the bounded immutable report, including unknown custom-option fields. Those fields are not interpreted. Known options and enum values are retained separately for detail. Current decoder module closure is explicitly `application-library-unqualified`; producer provenance and decoder qualification remain different identities. All results stay partial.

Adapter version `2` applies the [shared complete-report byte admission](source-linked-report-bounds.md), including the final content identity. A compact descriptor whose expanded fully qualified declaration metadata exceeds the existing 1 MiB report allowance fails in the producing owner.

The report uses the [common canonical evidence writer and detail consumer](source-linked-schema-evidence.md): original bytes/parser/generation checks, immutable sidecars, the existing provider sink, and verified target stores from the same generation. The authored `indexing/semantic/proto-linked-descriptor-evidence` fixture covers imported message and service-method types, Unicode/tab columns, unknown option wire retention, duplicate names, missing/cyclic imports, unsupported editions, stale generation and symbol bounds. Its producing receipt and parser inventory are synthetic; it does not prove native compiler or published-index acceptance.

Remaining work includes operational protoc/Buf discovery and version qualification, managed prerequisite/launch integration, observed decoder module closure, custom-option extension interpretation, edition feature qualification, public navigation/context integration and actual published-generation evidence. Existing protobufjs syntax/reflection routing and `buf.yaml` dialect ownership remain unchanged.
