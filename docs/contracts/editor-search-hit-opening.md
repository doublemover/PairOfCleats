# Original search-hit opening

The generic VS Code search-hit opener captures its original own passive path,
hash, coordinate unit and integer position fields before document work. The
selected repository root, resolved target, original open/display callbacks and
receivers remain with that request. Native awaits and later caller mutation
cannot replace its path or range. Returned document URI, version, closed state
and exact returned editor are checked before applying selection.

Rows without a source hash retain their existing contained local/remote file
opening and approximate position hints, including multiline clamping. Their
returned evidence is explicitly `unqualified-display-hint`; no source-byte or
exact indexed-range qualification is inferred. Rows with a supplied valid hash
use the existing contained local document authority. It verifies original bytes,
URI, supported buffer projection, version and clean state before and after
opening/display. A precise range additionally requires explicit `utf16` and full
positive integer coordinates. A verified hash without that range evidence opens
only the verified file; it cannot acquire an unqualified range as a substitute.
Hash-qualified remote source is unavailable through this local verifier.

Verified-file-only opening is an internal branch of the same document authority.
It derives its BOM-aware zero-length source position from that owner's original
verified bytes, rather than asking the caller for a separate preliminary read.
The branch cannot be combined with a caller range or span. Existing contained
descriptor, byte, buffer/version and before/after native-await checks remain;
the branch grants file opening without an exact indexed-range claim. The removal
of one redundant verification is source work, not a measured latency claim.

The extension forwards its original existing operation scope to each generic
open. Result-tree opening uses the same existing operation owner's private key
so a newer open revokes remaining original display/selection/reveal authority.
The revocation predicate is latched. A callback, position constructor or selection
setter that revokes the request cannot authorize subsequent UI actions. Native
work already accepted is awaited; this does not establish cancellation or
rollback. Tree display IDs and caller-supplied matching fields are not semantic
or private producer authority.

Original falsey or frozen open/display/introspection failures and independent
message inspection failures remain in immutable returned evidence through the
shared diagnostic snapshot. No stack preparation, error coercion or copied
release observation is needed to report failure. The result-tree normalization
preserves an explicitly supplied UTF-16 unit for the qualified branch.

Actual runtime/document/operation-owner and registered result-tree controls are
authored and **UNVALIDATED**. No tests, syntax/lint/format, bootstrap, editor/
native/child/IPC/browser/GPU/model, build or benchmark execution was performed.
File consistency observations are not an atomic snapshot. Canonical producer
coverage, real host behavior, native effects and resource/performance acceptance
remain separate. This source work does not authenticate arbitrary tree command
arguments or prove result-history membership.
