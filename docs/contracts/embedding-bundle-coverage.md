# Embedding bundle coverage receipts

Stage 3 may persist an `embeddingCoverageReceipt` version 1 on a selected incremental-manifest file entry after reading every selected immutable shard and proving that every chunk maps to a present merged vector. Empty bundles receive an explicit empty proof. A global completeness flag never substitutes for an individual receipt.

The proof binds the artifact surface, full source/dependency/bundle entry, complete current chunk-to-ordinal mapping inventory, embedding mode and identity, vector count, exact ordered vector ranges and their uint8 bytes. Its digest detects altered receipt fields. Mapping changes conservatively invalidate the inventory binding across files. A vector-only change invalidates only receipts containing that vector range.

Before reuse, Stage 3 opens the selected content-addressed bundle files and records their descriptor identity, size and nanosecond modification/change times. The observation also covers checksum and patch sidecars, including their absence, and refuses a patch writer lock. The existing immutable snapshot publication owner remains the authority. This is not a stat-only content identity for arbitrary mutable files, nor a qualification against hostile filesystem mutation. A missing file, changed sidecar, malformed proof or mismatched binding returns to the authoritative checksum-aware snapshot reader and ordinary fail-closed coverage evaluation.

Receipt admission is optional and bounded to 32,768 mapped chunks per file and the existing 8 MiB manifest allowance. Required metadata takes precedence if newly admitted proofs exceed that allowance. A proof-only repeat does not rewrite the manifest. Partial coverage, missing mappings and failed bundle rewrites never mint a complete proof or publish complete coverage.

Refresh results expose `work.bundleSnapshotsRead`, `bundleSnapshotsDecoded`, `chunksCompared`, `skippedByProof`, `receiptsRejected` and `invalidatedReasons`. These count source operations, not physical bytes, latency or a measured performance gain. The authored synthetic regression covers unchanged payload-read avoidance, empty bundles, source/dependency/mapping/identity changes, vector-only updates, partial extracted-prose coverage, malformed receipts and changed checksum sidecars. Execution, native filesystem race/crash qualification and performance measurements remain deferred.
