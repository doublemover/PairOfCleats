# Local type candidate ownership

Local type enrichment retains the complete annotation for each parameter, return and field. Generic arguments remain inside that type: `list[Optional[str]]` does not add `str` or `None` as types of the list parameter, and `Array<number>` does not turn that parameter into a `number`. Supported outer unions still add their actual alternatives. Bare, `typing` and `typing_extensions` `Optional`/`Union` constructors use their own balanced enclosure, so a later generic's closing bracket cannot be borrowed. Custom qualified constructors cannot supply standard nullability.

The existing inference owner inspects paired angle, square, round and brace delimiters outside escaped single/double/template literals. A quoted pipe/comma/bracket cannot create a candidate fragment. Malformed quoting/nesting, excessive lexical depth/length and unsupported outer function/conditional ownership preserve the complete annotation without speculative expansion. This is bounded lexical inspection, not complete type grammar validation or a language type checker.

Primitive alias lookup uses own, case-sensitive entries. Existing supported lowercase aliases and explicit JavaScript local-inference boxed aliases remain available. Case-distinct custom names and names such as `constructor`, `toString` and `__proto__` retain their identity. This local candidate policy is separate from [native textual type identity](native-type-expression-identity.md): the shared normalizer preserves boxed/primitive provider and declaration expressions rather than promoting a spelling alias into a native fact.

The actual cross-file parameter and return consumers receive these inferred facts without nested generic argument facts. Existing source-order literal/alias inference, confidence fields and container shape/element metadata remain separate owners. This repair does not establish lexical scopes, runtime narrowing, generic instantiation or exhaustive inference. The shared type-analysis producer identity must advance because persisted local metadata changes, although the canonical shared normalizer rules themselves do not change.

Authored local-enrichment and cross-file projection regressions cover literal separators, escaping, malformed and unsupported forms, generic ownership, distinct Python nullability, owned standard constructors, case/prototype names and bounded preservation. All are **UNVALIDATED**; no tests, format, syntax, bootstrap, compiler/provider/source execution or benchmark was run.
