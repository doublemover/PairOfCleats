# Original editor failure evidence

The semantic editor workflow retains exact thrown values through discovery,
typed consumer work, source opening, correction pickers and report recovery.
Falsey failures do not become cancellation or an unavailable diagnostic access.
A current consumer response that is not an object is unavailable evidence with
its exact returned value retained as the failure cause; it cannot silently reuse
a previous successful packet.

Failure diagnostics read the original message at most once. A throwing message
getter remains separate inspection evidence. Lazy stack, broad descriptor
projection, implicit string coercion and copied public owner fields are not
needed to display a failure. Original errors and inspection values remain exact
objects, so their independently owned observations remain available without
adoption or a claim that any native resource settled.

Notification and current-operation inspection failures are retained alongside
the original primary, including asynchronous notification rejection. A late old
notification cannot restore its previous report over a newer keyed workflow.
Recovery still permits another deliberate action or explicit generation entry;
no failed consumer or diagnostic getter is retried automatically. The previous
captured immutable payload/frontier remains available for deliberate copying.

Native commands may return immutable `editor-failure-evidence` with every
recorded original failure and its inspections. That private result does not
classify the entire workflow as success/failure: a later action may have
succeeded after recovery. The record preserves the failure rather than
discarding it or treating an attempted notification as proof of delivery.

Actual workflow/operation and registered-command controls are authored but
**UNVALIDATED**. No tests, syntax/lint/format, bootstrap, editor/child/native/IPC,
browser/GPU/model, build or benchmark execution was performed. Producer schemas,
generation/source qualification, real notification delivery, accepted UI
cancellation and resource/performance acceptance remain separate.
