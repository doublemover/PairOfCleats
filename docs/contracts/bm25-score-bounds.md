# BM25 score-bound execution

Broad JS BM25 may use a document-at-a-time WAND traversal when there are at least 2,048 posting rows, 2–64 active term/field cursors and a small requested top-k. Small workloads and selective domains retain the existing exhaustive/intersection owner. No persistent bound metadata or index-size increase is introduced. Request preparation inspects the relevant postings and current chunk weights before any pruning; that cost remains visible.

The supported bound domain requires admitted immutable sorted postings, valid global DF, positive integer TF, finite nonnegative document lengths, a positive bounded corpus average and finite positive field/chunk weights within the documented internal proof range. Current proof limits are `k1 <= 16`, weights in `[1e-6, 1e6]`, average length in `[1e-6, Number.MAX_SAFE_INTEGER]`, at most 64 contributions and query frequency at most one million. Existing BM25 parameter validation still runs first. Unsupported values select the original scorer without being clamped or reinterpreted. Boolean zero-score completion always uses that fallback.

Each cursor bounds BM25 saturation, query frequency, field multiplier and the maximum effective chunk weight observed on its posting list. Positive bound operations round upward; a 1,024-epsilon margin covers the bounded scalar accumulation envelope. Bounds may be loose. A pivot is skipped only when its accumulated bound is strictly below the current competitive score; cutoff equality remains eligible. Complete document scores use the original field-then-query-term order and apply the chunk weight after accumulation, preserving exact scores and deterministic ordinal ties.

Competitive complete scores feed the existing top-k reducer directly. The traversal retains term cursors and the bounded heap, with no matched-document score map. Cost records identify bound preparation rows, postings scored/skipped, fully scored documents, cursor count, map retention and fallback reason. Skipped score work is not a claim that the initial validation avoided reading those postings. Worst-case traversal can prune nothing and may cost more than exhaustive scoring.

The authored parity fixture compares the actual rankers with their retained exhaustive path for repeated/absent terms, weighted fields/body aliases, cutoff ties, high-weight late documents, negative/nonfinite fallback, selective domains, Boolean completion and deterministic broad no-pruning workloads. All fixture execution, adversarial numerical qualification and wall/CPU/allocation/RSS crossover measurements remain deferred. These are exact first-stage sparse candidate scores; downstream fusion and reranking retain their existing candidate scope.
